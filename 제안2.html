A

무엇을 예측했나?

현재 user 프롬프트가 제출된 직후, 바로 뒤에 오는 assistant 응답의 가시 텍스트 토큰 수를 예측했다. 비어 있지 않은 인접 user → assistant 쌍을 사용했다.

각 텍스트를 tiktoken의 o200k_base로 독립 계수했다. P10, P50, P90은 응답 길이의 낮은 값, 중앙값, 높은 값을 나타내는 예측 분위수다. 실제 API 청구량이나 전체 문맥 토큰 수는 아니다.

B

어떤 데이터를 사용했나?

AllenAI WildChat-1M의 14개 샤드 중 첫 샤드의 59,857개 대화 행에서 고정 표본을 만들었다. 전체 데이터의 무작위 표본은 아니다.

구분 정제 후 표본 사용자 프록시
학습 train 81,307쌍 8,702명
검증 validation 12,920쌍 1,736명
최종 test 11,942쌍 1,770명

기록시각 기준으로 기간을 나누고, 사용자와 대화 그룹이 분할 간 겹치지 않게 정제했다. test는 원래 23,222쌍에서 중복 사용자·그룹과 ID 결측 그룹 등을 제외했다. hashed_ip는 사용자 프록시이므로 실제 사람을 정확히 식별하지는 못한다.

모델에 무엇을 넣었나?

모델 입력 특징 수
A 현재 user 텍스트의 토큰 수, 문자 수, UTF-8 바이트 수 3
B A의 3개 + 이전 user 턴 수, 이전 1~3턴의 입력·출력 길이와 결측 지표 31

B는 이전 응답이 현재 프롬프트 전에 관측됐다고 가정한다. 유효하지 않은 과거 쌍도 턴 위치를 차지하며 결측으로 표시한다. 현재 응답, 미래 메시지, 사용자 ID, 주제·언어·임베딩은 입력하지 않았다. 이 샤드에서는 user 시각이 결측이라 턴 간격도 제외했다.

D

어떤 모델과 기준선을 비교했나?

A와 B 모두 LightGBM 분위수 회귀를 사용했다. P10·P50·P90을 각각 예측하고 음수만 0으로 잘랐다. 분위수 순서를 사후 정렬하지 않았다.

비교 대상 예측 방법
Fixed train 응답 길이의 경험적 분위수
Previous ratio 직전 응답 길이에 train에서 추정한 분위수별 비율을 곱함
Cumulative mean 같은 대화의 이전 유효 응답 평균과 train 잔차 분위수 사용
A 현재 프롬프트 길이만 사용한 LightGBM
B 현재 길이와 대화 이력을 사용한 LightGBM

이력이 없는 기준선은 fixed를 사용한다. 설정과 반복 횟수는 train 내부 시간 홀드아웃에서 선택했다. validation은 보고에만 사용했고 최종 test에 합치지 않았다.

어디까지 해석할 수 있나?

이 고정 표본에서 대화 길이 이력을 추가하면 후속 턴 예측에 유용하다는 결과를 얻었다. 최종 test는 사전에 고정된 설정으로 1회 평가했다.

  • 첫 샤드의 정제된 표본이므로 전체 WildChat이나 다른 서비스에 일반화했다고 볼 수 없다.
  • 기록시각은 실제 개별 요청 도착시각을 보장하지 않는다.
  • 신뢰구간에는 학습·모델 선택의 불확실성, 시간 상관, IP 식별 오차가 포함되지 않는다.
  • 실제 API 사용량, 비용, GPU 효율 또는 지연 개선은 측정하지 않았다.
  • BurstGPT의 다음 10분 집계 수요 예측은 별도 연구다.
