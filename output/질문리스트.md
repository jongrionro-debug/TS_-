# BurstGPT Proposal 예상 질문 — 보존 자료

> 2026-11-03 현재 이 문서는 기존 BurstGPT의 다음 10분 집계 수요 설계에 대한 문답이다. 아래 “현재”는 해당 설계를 가리킨다. WildChat의 개별 응답 길이 실험·최종 결과는 [PRD](../docs/project.md)와 [최종 보고서](../wildchat/results/test_final.md)를 따른다.

1. “12:11에 생성된 출력까지 포함하면, 다음 10분의 토큰량을 예측하는 게 아니지 않나요?”
“정확히는 다음 10분에 도착할 요청들의 총 토큰 수요를 예측합니다. 출력은 해당 요청의 최종 답변 전체를 포함하므로, 그 10분 동안 실제 생성된 출력량과는 다릅니다.”

인정해야 할 점: ‘다음 10분 토큰량’만으로 표현하면 오해가 생깁니다. 요청 도착 기준이라는 설명을 붙여야 합니다.
2. “왜 출력이 발생한 시각 대신 요청 도착시각으로 묶었나요?”
“새로 들어오는 요청들이 최종적으로 얼마나 많은 작업량을 가져오는지 보려는 설계입니다. 입력과 출력을 같은 요청 집합에 대해 계산할 수 있습니다. 또한 공개 로그에는 최종 출력 길이와 전체 응답시간만 있어, 출력 토큰을 실제 생성시각별로 정확히 나누기 어렵습니다.”

설명 포인트: 연구 목표에 따른 선택과 데이터의 제약을 함께 설명합니다. 이 방식이 실제 시간별 부하를 더 정확하게 나타낸다고 주장하지 않습니다.
3. “그럼 11:59에 들어와서 12:05까지 출력하는 요청은 빠지나요?”
“네. 현재 목표는 12:00~12:10에 새로 도착한 요청의 수요이므로 제외합니다. 따라서 이전에 들어와 아직 처리 중인 요청의 남은 작업량은 목표에 포함되지 않습니다.”

인정해야 할 점: 실제 서버 부하는 기존 미완료 작업과 신규 유입 작업 모두의 영향을 받습니다. 현재 목표는 신규 유입 수요만 다룹니다.
4. “그렇다면 이 예측으로 다음 10분에 필요한 GPU 수를 정할 수 있나요?”
“현재 결과만으로 바로 정할 수는 없습니다. 토큰 수요 예측은 용량 계획의 기초 정보가 될 수 있지만, GPU 수를 결정하려면 기존 미완료 작업, 처리 속도, 모델 종류와 지연 목표 등을 추가로 고려해야 합니다. 이번 프로젝트는 토큰 예측 오차까지 평가합니다.”

피해야 할 주장: 예측 정확도가 좋아졌다는 이유만으로 GPU 비용·전력·지연도 줄었다고 말하면 안 됩니다.
5. “12:11에야 알게 되는 출력량을 쓰면 미래 정보 누출 아닌가요?”
“미래 출력은 사후에 평가할 정답으로 사용합니다. 예측 입력에는 예측 시점 전에 완료된 응답의 출력량만 넣습니다. 또한 모델을 학습하는 시점에도 해당 정답이 모두 확정됐는지 확인합니다.”

구분할 점: 미래 값을 정답으로 삼는 것은 예측 문제의 기본 구조입니다. 문제가 되는 것은 미래 값을 예측 입력에 넣거나, 아직 확정되지 않은 정답으로 학습하는 것입니다.

현재는 이 규칙이 설계돼 있으며, 모델 구현 단계에서 실제 준수 여부를 검사해야 합니다.
6. “응답시간에 비례해서 출력을 나누면 실제 10분 생성량을 만들 수 있지 않나요?”
“추정은 가능합니다. 다만 전체 응답시간 동안 토큰이 일정하게 생성된다는 가정이 필요합니다. 응답시간에는 대기와 입력 처리도 포함될 수 있어, 균등 배분한 값을 실제 생성량이라고 볼 수는 없습니다.”

설명 포인트: 균등 배분은 별도의 가정이 들어간 대안입니다. 현재 실험에서는 적용하지 않았습니다.
7. “출력이 구간 밖으로 이어지는데, 10분이라는 기간을 선택한 의미가 있나요?”
“10분은 새로 도착할 요청을 모으는 예측 기간입니다. 모든 응답이 10분 안에 완료된다는 뜻은 아닙니다. 운영 준비 시간과 관측된 후속 요청 간격을 고려해 선택했으며, 최적 기간이라는 주장은 하지 않습니다.”

주의할 점: 후속 요청 간격 통계는 대화 활동을 살펴볼 근거입니다. 10분이 최적이거나 예측 성능이 가장 좋다는 증거는 아닙니다.
8. “이 문제 때문에 지금까지의 EDA도 잘못된 건가요?”
“현재 EDA는 요청 도착 기준의 최종 토큰 합계를 분석했으므로, 현재 정의 안에서는 유지됩니다. 다만 연구 목표를 ‘구간 안에서 실제 생성된 출력량’으로 바꾸면 출력 정답과 관련된 분포·상관 분석은 다시 구성해야 합니다.”

구분할 점: ID 품질, 요청 수, 입력 길이, 반복 대화 같은 분석은 활용할 수 있습니다. 출력 목표를 바꾸면 그 목표에 의존한 분석을 다시 확인해야 합니다.

발표에서 가장 먼저 아래 문장을 말해 두면, 이후 질문에 일관되게 답할 수 있습니다.
“저희의 예측 대상은 다음 10분에 도착할 요청들의 입력 토큰 합과 최종 출력 토큰 합입니다. 응답이 끝나는 시각은 구간을 넘을 수 있으며, 실제 10분간 생성량이나 GPU 부하를 직접 예측하는 것은 아닙니다.”
