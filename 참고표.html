교수님 피드백(① 왜 에이전트/자동화 트래픽인가? ② 이 예측이 산업에서 왜 필요한가?)과 시계열 과목의 정체성을 동시에 만족하기 위한 두 가지 핵심 대안 비교

공통 핵심 아이디어 (Model C의 진화): 단순히 모든 데이터를 하나의 모델에 넣고 피처 열(Column)만 늘리는 방식에서 벗어나, "요청·세션의 특성(행동 패턴 또는 프롬프트·상태 Semantic)을 먼저 분류한 뒤, 각 유형별 전용 예측 모델(Specialized Model)에 넣어 예측하는 분기 아키텍처"를 Model C로 삼는다.

1. 두 가지 후보 주제의 핵심 개념

옵션 1 · 거시적(Macro) 서버 시계열 접근

BurstGPT 내 행동 Feature 기반 Clustering 후
Cluster별 전용 시계열 모델로 총수요 예측

Research Question:
"110일간의 연속 LLM 서버 트래픽(API + 대화형)에서 전체 수요를 단일 시계열로 예측하는 것(A/B)보다, 활성 세션들을 행동 특성(고속 에이전트 루프형 / 장문 생성형 / 일반 대화형)으로 클러스터링하여 클러스터별 전용 모델로 예측·합산(C)하면 다음 10분 입·출력 토큰 수요를 더 정확히 맞힐 수 있는가?"
  • 기반 데이터: BurstGPT_3.csv (110일 연속, 총 534만 건: 기존 대화형 23만 건 + 그동안 제외한 API 로그 511만 건 활용 가능)
  • 시계열 단위: 매 1분 경계 $t$에서 향후 10분([t, t+600)) 서버 유입·처리 토큰 시계열
  • 핵심 차별점: 프롬프트 원문이 없는 대신, 세션의 초기 시계열 행동 지문(호출 간격, 입출력 비율, 토큰 누적 속도)으로 '에이전트성 워크로드'와 '인간 대화 워크로드'를 클러스터링해 각각 전용 모델로 예측
옵션 2 · 미시적(Micro) 세션 궤적 시계열 접근

Exgentic 에이전트 로그의 1차 차분($\Delta I_t$) 후
Semantic 국면별 전용 모델로 스텝별 시계열 예측

Research Question:
"멀티턴 에이전트 세션 내부의 진행 시계열($t=1, 2, \dots, N$)에서, 1차 차분된 컨텍스트 증가량($\Delta I_t$)과 출력($O_t$) 및 잔여 수요를 예측할 때, 단순 자기회귀 이력(A)과 도구 행동 피처(B) 대비 프롬프트·계획·에러 Semantic 국면(Regime)에 따라 전용 모델로 라우팅(C)하면 예측 오차가 얼마나 감소하는가?"
  • 기반 데이터: Exgentic/agent-llm-traces (6개 에이전트 벤치마크, 1,781개 세션, 약 3.5만 턴, 프롬프트·도구·토큰·시각 100% 포함)
  • 시계열 단위: 개별 에이전트 세션 내부의 턴 스텝 $t \to t+1$ (및 종료 시점 $T$까지의 누적 잔여 궤적)
  • 핵심 차별점: 실제 프롬프트 원문, TodoWrite 계획 진행률, Error 발생 여부를 직접 파싱하여 시계열의 국면 전환(탐색 / 순항 / 에러 루프 / 종료)별 전용 모델로 분기

2. 두 옵션에서 Model A / B / C는 각각 어떻게 구성되는가?

옵션 1 (BurstGPT 클러스터링)의 A / B / C
Model A (단일 집계 시계열 기준 모델) 세션 구분 없이 과거 1·2·3분 및 5·15·30·60분 전체 요청 수, 입력 토큰 합, 완료 출력 토큰 합, 입력 길이 분포, 시간대(24시간 주기)만 넣은 단일 XGBoost 모델
Model B (단일 모델 + 전체 활성 세션 상태 요약) Model A + 최근 5·15·30분 전체 활성 세션 수 및 전체 세션의 평균 최근성·연령·입력 변화를 하나의 모델에 열(Column)로 단순 추가
Model C (행동 Feature 클러스터링 + 클러스터별 전용 예측 모델) 1) 과거 로그에서 세션의 초기 행동 특성(호출 간격 $\Delta t$, 입력/출력 토큰 비율, 컨텍스트 증가율, 모델 종류)으로 K-Means / GMM 클러스터링 수행
  • Cluster 1: 초고속 연쇄 호출·입력 누적형 (자율 에이전트 / API 자동화 루프)
  • Cluster 2: 장문 응답 생성형 (코드 생성 / 문서 작성)
  • Cluster 3: 완만한 간격의 일반 대화형
2) 각 클러스터 $k \in \{1, 2, 3\}$별로 전용 시계열 예측 모델 $f_k$를 따로 학습해 예측한 뒤 합산 ($\hat{Y}(t) = \sum_{k=1}^K \hat{Y}_k(t)$)
옵션 2 (Exgentic 차분·시맨틱)의 A / B / C
Model A (단일 수치 자기회귀 시계열 모델) 메시지 원문을 보지 않고, 현재 턴 $t$, 1차 차분된 입력 토큰($\Delta I_t = I_t - I_{t-1}$), 시차 변수($\Delta I_{t-1}, O_t, O_{t-1}$), 누적 토큰, 응답 소요시간만 넣은 단일 모델
Model B (단일 모델 + 도구/액션 행동 피처) Model A + 이번 턴에 호출한 도구 개수(num_tool_calls), 도구 종류(search, show, finish), 도구 인자 길이, 직전 도구 반환 텍스트 길이를 단일 모델에 추가
Model C (프롬프트·상태 Semantic Router + 국면별 전용 예측 모델) 1) 프롬프트 원문(Task 복잡도, 도메인 유형), 에이전트 자가 계획(TodoWrite의 pending vs completed 비율), 직전 도구 실행 에러(has_error)를 파싱해 현재 턴의 Semantic 국면(Regime) 분류
  • Regime 1: 고복잡도 탐색 / 에러·디버깅 루프 국면 (토큰 재폭증 구간)
  • Regime 2: 일반 계획 순항 실행 국면 (선형 진행 구간)
  • Regime 3: 계획 완료 / 종료 선언 국면 (즉시 0 수렴 구간)
2) 판별된 국면별 전용 예측 모델 $f_{\text{regime}}$에 넣어 다음 턴 차분 토큰($\Delta I_{t+1}, O_{t+1}$) 및 잔여 토큰 예측

1. 시계열 과목 적합성
(Time-Series 정통성)		 매우 높음 (가장 안전)
  • 110일 연속 등간격(1분/10분) 달력 시간축 위에서 관측된 교과서적인 거시 시계열
  • 24시간 일중 계절성(Seasonality), 장기 추세(Trend), 자기상관(ACF), 버스트(Burstiness), 시간순 60/20/20 분할이 완벽히 성립함

  • 발표 시 '차분(Differencing)과 국면 전환(Regime-Switching) 시계열 모델링'임을 명확히 강조해야 함

 매우 명확 (스케줄러/KV캐시 직결)
  • 명분 1 (KV 캐시 메모리 예약): 다음 턴 컨텍스트 증가량($\Delta I_{t+1}$)을 알아야 수만 토큰짜리 KV 캐시 블록 할당/Eviction 결정 가능
  • 명분 2 (스케줄링 & 폭주 차단): 현재 세션이 Error 루프에 빠져 수십만 토큰을 더 쓸지, TodoWrite 계획을 다 끝내 곧 종료될지 알아야 서빙 우선순위(Shortest-Remaining-Job-First)와 예산 가드레일 작동 가능
4. 'Semantic' 활용 수준 간접적 (행동적 Semantic 추정)
  • 프롬프트 텍스트 원문이 없으므로 자연어 의미(NLP)는 사용 불가
  • 대신 호출 주기, 입력/출력 토큰 길이 비율, 응답 시간 등 수치적 행동 지문(Behavioral Fingerprint)을 통한 비지도 클러스터링으로 세션의 성격을 간접 분류
 직접적 (화이트박스 Semantic)
  • 초기 사용자 지시문(Task 원문), 호출한 도구 이름(search, Bash, finish), 에이전트 자가 계획(TodoWrite 완료율), 도구 응답 내 Error/Exception 텍스트를 직접 파싱해 분기 기준으로 사용
  • "왜 토큰이 늘어났는가?"를 텍스트와 도구 행동으로 명확히 설명 가능

4. 팀원들과의 의사결정 가이드 (어느 쪽을 선택할 것인가?)

  • 질문 2 (성능 향상의 확실성): "Model A 대비 Model B, Model C의 오차 감소폭(성능 개선 수치)이 확실하고 드라마틱하게 나오는 것이 가장 중요한가?"
    👉 이미 1개 샤드 예비 실험에서 -7.5% ~ -10.9% 오차 감소가 검증되었고 프롬프트·에러 원문의 인과관계가 뚜렷한 옵션 2 (Exgentic 차분·시맨틱)가 유리함 (옵션 1은 실제 클러스터링 실험으로 개선폭이 나오는지 먼저 확인 필요)
  • 질문 3 (교수님 피드백 대응): "교수님이 말씀하신 '에이전트 토큰 예측 + 왜 산업에서 필요한가'에 대해 프롬프트 원문과 도구(Bash, Search, TodoWrite, Error) 수준에서 깊이 있게 답하고 싶은가?"
    👉 그렇다면 실제 에이전트 메시지와 도구 호출이 살아있는 옵션 2 (Exgentic 차분·시맨틱)가 압도적으로 유리함
  • 질문 4 (일정 및 리소스): "기존에 만들어 둔 PRD와 발표 흐름, BurstGPT EDA 산출물을 최대한 살려서 안정적으로 완주하고 싶은가?"
    👉 그렇다면 기존 프레임워크 위에 '세션 클러스터링 기반 분기 예측(Model C)'만 얹는 옵션 1 (BurstGPT 클러스터링)이 유리함
