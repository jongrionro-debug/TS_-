# ADR-0004: 같은 대화 H1 순차 특징의 validation 전용 비교
- 상태: 채택
- 날짜: 2026-11-06
- 관련: Issue #23, [조건 C 결정](0003-wildchat-category-condition-c.md)

## 맥락

사용자가 #23에서 같은 대화의 이전 유효 응답을 누적한 H1을 B와 C_emb_PCA(k=32) 위에서 비교하도록 정했다. Mac의 탐색 파일은 이 체크아웃에 없으므로 이슈 명세로 구현한다. 예측 대상·첫 샤드 고정 표본·기존 사용자 분리 규칙은 유지한다. 완료된 최종 평가의 코드·설정·결과는 바꾸지 않는다.

## 결정

- H1은 현재 프롬프트 직후의 9개 수치다. 이전 유효 출력의 EWMA(α=0.3), 누적 평균·모집단 표준편차(ddof=0), 최근 두 유효 출력 차이와 원래 user 턴 간격당 기울기, 직전 유효 출력/입력 비율과 그 EWMA, 현재/직전 유효 입력 배율, 과거 관측 수다.
- 상태 키는 원본 source 대화다. 사용자나 중복 그룹의 다른 대화를 섞지 않는다. 유효하지 않은 쌍은 누적하지 않으며 원래 턴 번호의 간격은 유지한다. 특징 snapshot 후 현재 응답을 갱신한다. 현재 입력 길이는 예측 시점에 관측 가능하다.
- EWMA는 첫 유효 값으로 초기화하고 이후 `0.3 * 새 값 + 0.7 * 이전 EWMA`로 갱신한다. 이력이 없으면 count=0 외에는 NaN, 한 개면 std=0, 두 개 미만이면 차이·기울기는 NaN이다. 입력 0의 비율은 NaN이며 비율 EWMA에서만 건너뛴다.
- B, B+H1, C_emb_PCA, C_emb_PCA+H1은 같은 #13 정제 train/validation 및 train 내부 시간 홀드아웃을 쓴다. 각 조건에 같은 3개 후보·500회 상한·40회 조기 종료를 적용한다. 설정·반복 수는 각 조건의 내부 행 가중 pinball로만 선택한다. #19의 B 설정 고정 PCA 결과와 구별한다. k=32는 이슈에서 미리 고정했다.
- PCA는 내부 선택 시 fit 행만, validation 예측 시 전체 정제 train만으로 적합한다. 새 의존성 없이 기존 로컬 SVD PCA를 사용한다.
- 이슈 본문에는 캐시 재생성이 있으나, 이번 실행의 명시적 운영자 지시가 기존 캐시 재사용으로 이를 구체화했다. 기존 PCA 결과에 기록된 SHA256·형식·유한값·키 유일성·train/validation 키 전체 일치를 검증한다. 불일치하면 중단한다. 원문을 다시 읽거나 캐시를 자동 생성하지 않는다.
- validation의 첫/후속/전체 턴×행/사용자 가중 pinball과 두 H1 추가 차이를 보고한다. 동일 사용자 paired bootstrap 1,000회·seed 42·PCG64·선형 보간 percentile 95% CI를 모든 조건·턴·가중에 공유한다. 재선택·재학습·분위수 정렬은 하지 않는다.
- 실행 중 JSONL 열기를 train/validation 두 입력 경로로 제한한다. 실제 다른 분할이나 완료된 최종 평가를 재실행하지 않는다.

## 결과와 한계

원문·식별자·모델 바이너리는 저장하지 않고 집계 JSON·Markdown·로그만 남긴다. [실행 결과](../../wildchat/results/temporal_h1.md)와 [재현 명령](../../wildchat/README.md)에 연결한다. validation을 반복 관측한 후속 분석이며 Mac 탐색 결과의 독립 확증이 아니다. CI는 고정된 학습·선택 결과에 조건부이고, 전체 WildChat이나 실제 API/GPU 효과를 뜻하지 않는다.
