# 프로젝트 기획서: 대화 상태를 활용한 LLM 입력·출력 토큰 수요의 단기 예측

- 과목: 시계열 데이터 분석 및 실습
- 문서 작성일: 2026-10-22
- 문서 상태: 연구 설계 초안 — 주제 확정, 대화형 데이터 품질 확인 및 모델 실험 예정
- 주 데이터: BurstGPT_3
- 용도: 팀 내 연구 범위 합의, Proposal 작성, 분석·실험 구현의 기준

## 1. 프로젝트 개요

### 1.1 연구 질문

> 대화형 서비스에서, 과거 요청량·토큰량에 최근 대화 상태 정보를 추가하면 다음 5분의 입력·출력 토큰 수요를 더 잘 예측할 수 있는가?

매 1분 경계에서 당시까지 관측 가능한 정보를 사용해, 다음 5분 동안 도착할 대화형 요청들의 입력 토큰 합과 최종 출력 토큰 합을 각각 예측한다. 집계 이력만 사용하는 기준 모델에 활동 대화 수와 대화 상태 요약을 단계적으로 추가하여, 각 정보 묶음의 추가 예측가치를 평가한다.

핵심 기여 후보는 새로운 예측 알고리즘이 아니라 **집계 이력에 대화 연결 정보를 추가하는 것이 유용한지 공정한 비교로 확인하는 것**이다. 성능 향상은 아직 검증되지 않았으며, 개선이 없거나 특정 조건에서만 나타나는 결과도 보고한다.

### 1.2 문제의 중요성

동일한 요청 수라도 요청당 입력·출력 길이에 따라 토큰량이 달라진다. 또한 동일한 최근 토큰량이 소수 대화에 집중됐는지, 여러 대화에 분산됐는지에 따라 후속 요청의 발생과 길이 구성이 다를 가능성이 있다.

단기 토큰 수요 예측은 서비스 용량 계획을 위한 기초 정보가 될 수 있다. 다만 이 프로젝트는 토큰 예측 정확도를 평가하며, 실제 GPU 이용률·처리량·비용 절감·SLO 개선을 입증하지 않는다.

### 1.3 현재 설계에서 고정하는 사항

| 항목 | 결정 |
|---|---|
| 주 분석 대상 | `Log Type == "Conversation log"`인 요청 |
| 예측 시점 간격 | 원본 Timestamp의 60초 경계마다 1회 |
| 예측 대상 구간 | `[t, t + 300초)` |
| 모델 출력 | 다음 5분 누적 입력 토큰, 다음 5분 도착 요청의 최종 출력 토큰 |
| 모델 구성 | 입력·출력 각각 별도의 XGBoost 회귀 모델 |
| 핵심 비교 | A: 집계 이력 → B: 활동 대화 수 추가 → C: 대화 상태 추가 |
| 평가 원칙 | 시간순 분할, 동일 예측 시점, 동일 튜닝 예산, 관측 시점 준수 |

현재 정답은 **누적 토큰 두 값**이다. 향후 1분 토큰량 5개를 각각 예측하는 다중 지평 문제와 구분한다.

기존 기획의 ‘배경 수요 + 세션별 후속 수요 합산’은 이번 기본 구현에 포함하지 않는다. Session ID별 독립 모델도 만들지 않는다. 대화별 상태를 계산한 뒤 전체 대화형 서비스의 설명변수로 요약한다.

### 2.4 시간 해석

관리자 답변에 따르면 시간대는 UTC+8이며 서머타임은 없다. 기준 달력 날짜는 확인되지 않았다. [관리자 답변](https://github.com/HPMLL/BurstGPT/issues/9)

- 하루 중 시각은 원본 `Timestamp % 86400`으로 계산한다.
- 최소 Timestamp를 뺀 경과시간은 시각화에 사용하되, 하루 중 시각과 혼용하지 않는다.
- 실제 날짜·월요일·주말·공휴일을 임의로 부여하지 않는다.
- 24시간·7일 반복은 상대시간으로 탐색할 수 있다. 7일 순환위상과 실제 요일명은 구분한다.

## 3. 예측 문제와 정보 이용 시점

### 3.1 목표값

대화형 요청 i의 도착시각을 a_i, 입력 토큰을 x_i, 최종 출력 토큰을 r_i라고 한다.

```text
Y_input(t)  = sum(x_i for requests with t <= a_i < t + 300)
Y_output(t) = sum(r_i for requests with t <= a_i < t + 300)
```

두 값 모두 요청 도착 시각을 기준으로 묶는다. 출력 합계에는 t+300 이후에 생성된 출력도 포함될 수 있다. 따라서 ‘그 5분 동안 실제 생성된 토큰량’이 아니다.

출력 0 요청은 기본적으로 유지한다. 이때 출력 목표는 **기록된 실제 출력량**이며 실패가 없었다면 발생했을 잠재 출력 수요가 아니다. 출력 0의 원인을 CSV만으로 특정하지 않는다.

미래에 처음 등장하는 대화와 상태 추적 대상 밖의 대화도 목표값에 포함한다. 상태를 계산할 수 있는 대화의 후속 요청만 정답으로 고르면 연구 대상이 바뀐다.

### 3.2 요청 도착과 응답 완료의 구분

요청 완료시각은 `c_i = Timestamp_i + Elapsed time_i`로 구성한다. 이를 사용하기 전에 Elapsed time의 자료형·결측·음수·극단값과 완료시각 정합성을 점검한다.

| 정보 | 예측 시점 t에서의 사용 조건 |
|---|---|
| 요청 시각·입력 길이·대화 ID·모델 | `a_i < t` |
| 최종 출력 길이·최종 응답시간 | `c_i < t` |
| 미래 도착 요청의 정보 | 입력 특징에는 사용하지 않음 |
| 미래 토큰 합계 | 사후 정답 계산에만 사용 |

기본 설계는 요청 도착 정보가 지연 없이 관측 가능하다고 가정한다. 실제 로그 수집 지연은 공개 CSV로 확인할 수 없으므로 보고서에 가정을 명시한다.

### 3.3 과거 출력 특징의 정의

주 실험 A/B/C에는 **완료시각 기준 출력 이력**을 동일하게 제공한다.

```text
completed_output_last_5min(t)
    = sum(Response tokens for requests with t-300 <= c_i < t)
```

이는 완료된 요청의 전체 출력량을 완료시점에 기록하는 통계이며 순간 GPU 생성률이 아니다. 도착 기준 목표 `Y_output`과 별도로 이름 붙인다.

완료시각 품질 문제로 이 특징을 구성할 수 없다면 임의로 채우지 않는다. 전체 비교에서 공통으로 제외하고 연구 질문을 ‘과거 요청량·입력 토큰량 대비’로 조정한다. 이 변경은 실험 설정에 기록한다.

### 3.4 학습 정답의 확정 시점

모델 학습·재학습 시각을 T라고 할 때 입력 정답은 해당 5분 구간이 끝난 표본만 사용한다. 출력 정답은 구간이 끝나고 그 안의 요청들이 모두 완료된 표본만 사용한다.

```text
입력 학습 가능: t + 300 <= T
출력 학습 가능: t + 300 <= T AND 해당 구간 모든 요청의 c_i < T
```

빈 구간도 종료 전에는 0으로 확정할 수 없다. 최종 CSV에 값이 있다는 이유만으로 학습 시점에 이미 알았다고 가정하지 않는다. 학습·검증 경계에 5분만 비우는 방식은 오래 걸린 응답의 정답 누출까지 보장하지 않는다.

## 4. 연구 가설과 비교 실험

### 4.1 가설

| 가설 | 내용 | 비교 |
|---|---|---|
| H1 | 최근 활동 대화 수가 집계 수요 이력에 추가 예측가치를 제공한다. | B 대 A |
| H2 | 대화 상태 요약이 활동 대화 수를 넘어 추가 예측가치를 제공한다. | C 대 B |
| H3 | 대화 정보의 전체 추가 효과는 입력·출력 목표에서 다르게 나타날 수 있다. | C 대 A를 목표별로 평가 |

이는 예측 가설이며 인과 가설이 아니다. 대화 정보가 수요를 발생시키는 원인임을 증명하지 않는다. 입력에서만 개선되면 입력에 대한 근거로 보고한다. 가설이 지지되지 않는 결과도 유지한다.

### 4.2 특징 묶음

| 모델 | 특징 구성 |
|---|---|
| A: 집계 기준 모델 | 과거 요청 수·입력 토큰 합·완료 기준 출력 토큰 합의 지연값과 이동통계, 최근 요청들의 입력 길이 분포, 하루 중 시각 |
| B: 활동 대화 추가 | A + 최근 5·15·30분의 고유 유효 Session ID 수 |
| C: 대화 상태 추가 | B + 최근 30분 관측 대화들의 최근성·관측 요청 횟수·관측 연령·마지막 입력 길이·입력 길이 변화 요약 |

초기 후보 이동창은 5·15·30·60분으로 제한한다. 지연값은 직전 1·2·3분부터 시작한다. 변수 선택은 검증 구간에서만 수행한다. 모델별 요청 구성비를 사용하면 A/B/C에 공통으로 제공한다.

### 4.3 집계 기준 모델의 강도

A에도 ID 연결 없이 계산 가능한 최근 입력 길이 평균·표준편차·소수의 분위수 등을 제공한다. 그래야 C의 개선이 단순히 입력 길이 통계를 추가했기 때문인지 혼동하는 문제를 줄일 수 있다.

예를 들어 A의 ‘최근 모든 요청의 입력 길이 중앙값’과 C의 ‘각 활동 대화의 마지막 요청을 하나씩 골라 구한 입력 길이 중앙값’은 다르다. 후자는 대화 연결을 활용한 특징이다.

그래도 결론은 ‘설정한 집계 기준특징 대비 추가 가치’로 한정한다. 집계 정보로 표현할 수 있는 모든 예측 가능성을 배제했다는 의미는 아니다.

### 4.4 대화 상태의 정의

활동 대화는 실제 종료 여부와 무관하게 **최근 30분에 한 번 이상 요청이 관측된 대화**로 정의한다. Session ID는 모델에 그대로 인코딩하지 않고 연결키로 사용한다.

| 상태 | 계산 및 요약 예시 |
|---|---|
| 최근성 | t에서 마지막 과거 요청시각을 뺀 값; 중앙값·분위수 |
| 관측 요청 횟수 | t 이전 파일 내 요청 수; 1회 대화 비율·2회 이상 대화 수 |
| 관측 연령 | 최초 관측 요청부터 t까지의 시간; 중앙값 |
| 마지막 입력 길이 | 대화별 마지막 과거 요청의 입력 길이; 중앙값·상위 분위수 |
| 입력 길이 변화 | 과거 요청이 2개 이상인 대화의 마지막 두 입력 길이 차이; 중앙값 |
| 과거 요청 간격 | 대화 내 과거 제출 간격; 선택적 확장 특징 |

관측 횟수와 연령은 파일 이전 이력을 포함하지 않는다. 모든 요약은 t 이전 기록으로 계산한다. 전체 CSV에서 얻은 최종 세션 길이·마지막 시각·미래 반복 여부는 입력으로 사용하지 않는다.

활동 대화가 없으면 대화 수는 0으로 기록한다. 정의되지 않는 중앙값·변화량은 결측으로 두고 활동 여부·계산 가능한 대화 수를 함께 제공한다. 실험별로 결측 행을 다르게 삭제하지 않는다.

## 5. 데이터 품질과 전처리 요구사항

1. 전체 대화형 표본을 사용한다. 무작위 요청 추출로 대화 연결을 끊지 않는다.
2. 대화형만의 최소·최대 시각, 일별 관측량, 긴 빈 구간을 점검한다.
3. Session ID의 결측·빈 문자열·공통 대체값 여부, 고유 ID 수와 반복 대화 비율을 확인한다.
4. ID 없는 요청도 기본 목표값에는 포함한다. 상태특징은 유효 ID에서 계산하고 ID 관측률을 보고한다. 결측 ID들을 하나의 대화로 합치지 않는다.
5. 미래에 2회 이상 나타난 ID만 골라 전체 실험을 진행하지 않는다. 미래 반복 여부로 표본을 선택하면 전체 대화형 서비스라는 목표와 달라진다.
6. 토큰 결측·비수치·음수 및 `Total tokens` 정합성을 점검한다. 문제 건수와 처리 규칙을 기록한다.
7. 중복 행과 출력 0 요청을 자동 삭제하지 않는다. 변경이 필요하면 근거와 영향 범위를 남긴다.
8. 내부 빈 분은 연속 수집 가정 아래 0으로 집계할 수 있으나, 실제 무요청과 수집 누락을 구분할 수 없음을 명시한다.
9. 최대 과거창을 확보하는 초기 준비 구간과 완전한 미래 5분을 구성할 수 없는 끝부분은 평가에서 제외한다. 모든 모델에 같은 적격 시점 규칙을 적용한다.
10. 요청 도착이 없는 기간까지 실제 수집이 지속됐는지 확인할 수 없으므로, 관측 범위 밖으로 임의의 0 구간을 연장하지 않는다.

## 6. 시계열 EDA 계획

| 분석 | 목적 |
|---|---|
| 대화형 1분 요청 수·입력량·출력량 | 주 분석 대상의 변동과 빈 구간 확인 |
| 5분·1시간 집계 및 구간 확대 | 압축된 전체 그래프에서 가려진 시간 구조 탐색 |
| 자기상관과 시간대별 분포 | 단기 의존성과 반복 패턴이 존재하는지 확인 |
| 요청 수와 요청당 입력 길이의 분리 | 토큰 피크가 요청 증가인지 길이 증가인지 탐색 |
| Session ID 반복 횟수·간격 분포 | 대화 상태를 활용할 데이터 근거 확인 |
| 비슷한 과거 수요에서 활동 대화 수 비교 | 추가 정보가 있을 가능성을 탐색; 인과효과로 해석하지 않음 |

추세·계절성은 존재를 가정하지 않고 확인한다. 대화 상태는 내부 로그에서 만든 설명변수이며 외부 데이터나 엄밀한 외생변수로 부르지 않는다. EDA에서 보이는 연관성은 미래 예측력의 증거와 구분한다.

## 7. 모델 학습 및 평가

### 7.1 기본 구현

- 입력·출력 각각 A/B/C를 학습하여 총 6개 XGBoost 모델을 비교한다.
- 먼저 다음 5분 토큰 합계를 직접 예측한다. 요청 수와 평균 길이를 별도로 예측해 곱하는 구조는 기본 범위에서 제외한다.
- 목표별 공통 목적함수, 공통 탐색 범위와 튜닝 예산을 사용한다. 선택은 검증 성능으로 수행한다.
- 음수 예측이 발생하면 0으로 제한하는 등 출력 규칙을 사전에 정하고 모든 모델에 동일하게 적용한다.
- 지수가중 평균·가중 활동 대화 수는 기본 실험 이후 선택적 비교로만 추가한다.

### 7.2 시간순 분할

대화형 관측범위를 확인한 뒤 상대시간 기준으로 대략 학습 60%·검증 20%·평가 20%를 초기안으로 정한다. 정확한 경계는 모델 성능을 보기 전에 저장한다. 불연속 수집 의심 구간이 있으면 먼저 처리 방침을 확정한다.

검증에서 특징·설정을 정하고 최종 평가 구간은 고정한다. 재학습을 수행한다면 재학습 시각과 사용 가능한 정답 표본을 기록한다. 동일한 목표의 A/B/C는 같은 학습 적격 시점과 평가 시점을 사용한다.

평가 기간의 이미 관측된 요청을 이후 예측의 특징으로 사용하는 것은 허용한다. 평가 정답으로 모델·특징을 고르는 것은 허용하지 않는다. 두 기간에 걸쳐 지속되는 동일 대화의 과거 관측을 사용하는 것은 실제 운용과 일치한다.

### 7.3 단순 기준 예측

입력 토큰에는 직전 5분 합계 유지 예측을 포함한다. 전날 같은 구간 예측은 데이터가 충분히 연속적이고 과거 구간이 확보된 경우 추가한다.

출력 토큰에서는 직전 5분 도착 요청들의 최종합이 아직 확정되지 않을 수 있다. 따라서 완료 기준 최근 출력량 또는 예측 시점에 이미 확정된 과거 구간을 사용하는 기준을 명시한다. 완료 기준 값과 도착 기준 목표의 차이를 숨기지 않는다.

### 7.4 성능 지표와 해석

| 지표·결과 | 역할 |
|---|---|
| 입력·출력별 MAE | 주 평가 지표; 원래 토큰 단위 |
| 입력·출력별 RMSE | 큰 오차에 대한 보조 평가 |
| B−A, C−B, C−A 개선폭 | 특징 묶음의 추가 가치 |
| 날짜별·연속 기간별 오차 차이 | 개선의 일관성과 시기 의존성 |
| 높은 토큰 수요 구간 오차 | 큰 수요에서의 성능; 기준은 학습 자료에서 정함 |

0인 목표 구간이 있을 수 있으므로 MAPE를 주지표로 사용하지 않는다. 개선율 계산 시 기준 오차가 0이면 비율은 정의하지 않는다.

1분마다 예측하는 5분 목표는 서로 겹친다. 분별 오차를 독립 표본으로 가정한 검정을 기본으로 사용하지 않는다. 날짜별 짝지은 오차 차이를 보고하고, 가능하면 연속 시간 블록을 유지하는 bootstrap으로 개선폭의 불확실성을 제시한다. 블록 길이와 검정 방식은 평가 성능을 보고 선택하지 않는다.

입력과 출력의 결과는 별도로 판단한다. 성능이 좋아진 특정 구간만 골라 결론을 내리지 않는다. 지표가 엇갈리면 MAE를 우선하되 RMSE와 높은 수요 구간의 악화도 함께 보고한다.

## 8. 선행연구 및 프로젝트 차별성

### 8.1 이미 수행된 연구

- BurstGPT 원 논문은 대화형·API 패턴과 대화별 요청 횟수·간격을 분석했다. 또한 집계 이력과 시간 정보를 사용하는 XGBoost 예측을 제시했다. [원 논문 §3, §5.4](https://arxiv.org/html/2401.17644v5)
- PreServe는 서비스 단위 토큰 수요와 개별 요청 부하를 예측하는 관리 프레임워크를 제시한다. 토큰 수요 예측 자체는 새로운 문제라고 주장하지 않는다. [PreServe](https://arxiv.org/abs/2504.03702)

### 8.2 이번 프로젝트의 기여 후보

> 집계 이력 기반 예측을 출발점으로, 최근 활동 대화 수와 대화별 관측 상태를 요약한 특징이 다음 5분 누적 입력·출력 토큰 예측에 추가 가치를 제공하는지 동일한 평가 조건에서 단계적으로 검증한다.

프로젝트의 차별성은 A/B/C 비교로 확인할 **대화 연결 정보의 추가 예측가치**에 있다. Session ID 사용, 입력·출력 분리, XGBoost 적용 자체를 최초의 기여로 주장하지 않는다.

원 논문과 목표·평가 기간·설정이 다르므로 ‘원 논문에 착안한 기준 모델 재구성’으로 표현한다. 원 논문의 수치와 직접 비교하여 우월성을 주장하지 않는다. 전체 관련 문헌에서 최초라는 주장에는 별도의 체계적인 문헌검토가 필요하다.

### 8.3 허용하는 결론의 범위

- 가능: 이 데이터·목표·평가 구간에서 C가 A보다 어느 정도 개선됐는지 설명.
- 가능: 입력과 출력, 평상시와 높은 수요 구간에서 효과가 달랐는지 설명.
- 가능: 충분한 집계 특징을 제공하면 대화 정보의 추가 효과가 작았다는 결과.
- 불가: 대화 상태가 수요를 유발하는 인과효과를 증명했다는 결론.
- 불가: 토큰 오차 개선만으로 GPU 비용·SLO·실제 처리량이 개선됐다는 결론.
- 불가: 다른 서비스·모델·지역에도 동일하게 일반화된다는 단정.

## 9. 수업 Proposal 구성

### 9.1 Problem statement

대화형 LLM 서비스에서 매 1분마다 다음 5분에 도착할 요청들의 입력·최종 출력 토큰 합계를 각각 예측한다. 과거 요청·토큰 이력에 최근 대화 상태를 추가했을 때 예측이 개선되는지 평가한다. 단기 수요 정보는 용량 계획의 기초가 될 수 있으나, 본 연구는 예측 성능 평가에 집중한다.

### 9.2 Dataset

공식 출처, 전체 원본 5,344,021행과 대화형 분석 표본 233,617행을 구분해서 제시한다. 원자료는 요청 이벤트이며, 이를 1분 예측 시점과 다음 5분 목표로 변환한다. 대화형만의 정확한 기간·ID 품질은 후속 점검 결과를 반영한다. 실제 달력 날짜는 제시하지 않는다.

### 9.3 Rationale and novelty

최근 수요의 지속성·변동성 및 대화 후속 요청의 시간적 관계를 분석할 수 있어 시계열 문제에 적합하다. 외부 변수나 뚜렷한 계절성의 존재를 전제할 필요는 없다. 기존 집계 예측을 기준으로 활동 대화 수와 상태 정보를 단계적으로 추가하여 효과를 분리하는 것이 이번 프로젝트의 차별점이다.

### 9.4 Proposal에서 결과를 설명하는 수준

실제 확인된 데이터 통계와 예비 EDA만 결과로 제시한다. 대화 정보의 성능 향상은 가설로 표현하고, 비교 방법·평가 기준·한계를 제시한다. 임의의 향상률을 약속하거나 아직 실행하지 않은 모델 결과를 작성하지 않는다.

## 10. 실행 단계와 산출물

| 단계 | 주요 작업 | 완료 산출물 |
|---|---|---|
| 1. 대화형 품질 점검 | 관측 범위·ID·토큰·완료시각·빈 구간 확인 | 실행된 EDA와 품질 요약표 |
| 2. 특징·정답 구성 | 시점별 A/B/C 특징, 두 정답, 정답 확정시각 | 재현 가능한 생성 코드와 변수 사전 |
| 3. 분할·기준 모델 | 시간 경계 고정, 단순 기준과 A 구현 | 설정 파일과 검증 결과 |
| 4. 비교 실험 | 동일 조건에서 B/C 학습 | 입력·출력별 비교표 |
| 5. 해석·보고 | 기간별 오차·높은 수요 구간·한계 분석 | 예측 그래프, 결과표, 발표 자료 |

모델 구현은 데이터 품질과 특징·정답 정의가 확인된 뒤 진행한다. 각 단계의 코드는 실행 결과를 남기고, 원본 해시·라이브러리 버전·분할 경계·난수 시드·특징 목록·모델 설정을 기록한다.

## 11. 완료 기준

- [ ] 전체 원본과 대화형 분석 표본을 구분해 규모·기간·품질을 보고했다.
- [ ] Session ID 결측·공통값·반복 비율을 확인하고 처리 방침을 기록했다.
- [ ] 다음 5분 누적 입력·출력 정답이 요청 단위 합계와 일치한다.
- [ ] 특징에 예측 시점 이후의 요청 또는 미완료 출력이 유입되지 않는다.
- [ ] 학습 표본의 정답이 학습 시각에 확정됐는지 검사했다.
- [ ] 과거 데이터까지만 사용한 특징과 전체 자료에서 해당 시점까지 잘라 계산한 특징이 일치한다.
- [ ] A/B/C의 평가 시점, 정답, 모델 계열, 튜닝 예산이 공정하게 맞춰졌다.
- [ ] 입력·출력별 MAE·RMSE와 기간별 결과를 모두 보고했다.
- [ ] 향상 여부와 무관하게 가설의 지지·불지지 및 한계를 기록했다.
- [ ] 새 환경 또는 깨끗한 커널에서 핵심 분석을 재실행할 수 있다.

**프로젝트 완료는 성능 향상을 반드시 달성하는 것이 아니라, 정의된 질문을 누출 없이 공정하게 평가하고 결과를 재현 가능하게 보고하는 것이다.**

## 12. 범위 밖의 작업과 변경 관리

다음은 기본 범위에 포함하지 않는다: 세션별 후속 확률 모델, 배경·세션 수요 분해, API 포함 전체 서비스 확장, 의미 정보 복원, GPU 시뮬레이션, 서버 배치·라우팅 최적화, 비용·SLO 평가, 확률 예측·경보 시스템 구축.

대화형 ID가 대부분 유효하지 않거나 반복 대화가 매우 적으면 데이터 적합성을 재검토한다. 이 경우 유리한 일부 표본만 사후 선택하지 않고, 대상 범위 변경 또는 가설의 한계를 문서화한다.

목표 구간, 분석 대상, 출력 정보의 이용 범위, 특징 묶음 또는 평가 규칙을 바꾸면 변경 이유와 시점을 기록한다. 이전 문서의 배경 수요 분해나 다중 지평 구상을 이번 설계에 자동으로 혼합하지 않는다.
