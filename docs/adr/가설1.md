# 코딩 에이전트 토큰 수요 예측으로의 전환 검증

- 정리일: 2026-10-28 / 원본 분석·예비 실험 수행일: 2026-10-27
- 목적: 교수님 피드백에 따른 연구 대상 전환의 타당성 검증 결과 공유
- 상태: 공개 데이터 확보·품질 검사·예비 실험 완료. **전환안을 아직 PRD에 반영하지 않음**
- 현재 연구 정본: [docs/prd.md](../../docs/prd.md)
- 현재 위치(2026-11-03): TraceLab·Exgentic 전환 후보의 과거 검토 기록. 채택된 현재 작업은 WildChat의 개별 응답 길이 예측이며 [ADR 0002](../decisions/0002-wildchat-request-forecast.md)와 [최종 결과](../../wildchat/results/test_final.md)를 따른다. 아래 추천·미결정 사항은 2026-10-28 당시 맥락이다.

## 1. 핵심 결론

**조건부로 전환 가능하다. 다만 예측 목표와 활동 상태의 정의를 수정해야 한다.**

TraceLab 공개 원본을 확보해 전체 구조·시간·토큰 품질을 집계하고, Codex 기록으로 기준 예측과 A/B/C 예비 실험까지 수행했다. 분석 코드·원본·예측 테이블·결과는 [eda/agent_transition/](../../eda/agent_transition/)에 저장했다.

현재 후보에는 검증된 서버 요청 도착시각이 없다. 따라서 기존의 **“다음 10분에 도착할 요청들의 입력·최종 출력 토큰 합”**을 그대로 옮길 수 없다. 실제로 실행한 대안은 **“다음 10분에 사용량이 보고될 호출들의 입력·출력 토큰 합”**이다. 두 문제는 서로 다르다.

보고 기준 문제는 학기 프로젝트 규모에서 실행할 수 있었다. 그러나 최근 세션 수·상태를 추가했을 때 **일관된 성능 향상은 확인되지 않았다**. 이번 C는 세션별 사용 이력 요약이며, 현재 실행 중 여부나 도구 대기 같은 실행 상태의 효과는 미검증이다.

**서버 도착 기준의 선제적 수요예측을 반드시 유지한다면, 현재 후보만으로 전환하는 것은 권하지 않는다.** 호출 시작·사용량 확정·실행 상태가 연결된 다른 데이터가 필요하다.

## 2. 기존 프로젝트와 대조한 내용

[프로젝트 지침](../../AGENTS.md), [PRD](../../docs/prd.md), [Proposal PDF](../../output/Token%20Demand%20Forecasting%20%E2%80%94%20Proposal.pdf), [EDA 노트북](../../eda/eda.ipynb)과 [관련 결과](../../eda/results/)를 필요한 범위에서 확인했다.

기존 설계는 BurstGPT_3의 Conversation log를 대상으로 매 1분에 다음 10분 동안 도착할 요청들의 입력·최종 출력 토큰 합을 각각 예측한다. 출력에는 구간 종료 이후에 생성된 토큰도 포함될 수 있다. A는 집계 이력, B는 활동 대화 수, C는 대화 상태 요약을 추가한다. XGBoost를 사용하고, 동일 예측 시점·튜닝 예산·시간순 분할·관측 가능 시점으로 비교한다.

이번 작업에서는 PRD·발표·BurstGPT 원본·기존 EDA를 보존했다. 자격증명이나 개인 에이전트 대화 기록에는 접근하지 않았다. 공개 데이터 다운로드와 로컬 분석만 수행했으며 Git stage·commit·push는 하지 않았다.

### 3.2 연결키와 시간 정보

`session_id`는 호출을 묶는 연결키다. Codex의 `turn_id`는 216,823행 중 195,781행에 있으며 Claude에는 없다. 공개 스키마에 명시적인 부모·하위 에이전트 관계가 없어 전체 사용자 작업·실행 트리를 복원할 수는 없다. ID 자체를 모델의 예측 변수로 인코딩하지 않았다.

| 시각·정보 | 확인 범위와 해석 |
|---|---|
| 서버 요청 도착 | 직접 기록된 필드 없음 |
| 입력 준비 | 첫 출력 전 마지막 `user_message`·`tool_result`를 대리 시각으로 만들 수 있으나 서버 도착과 다름. Codex 36,535행에서 이 대리 시각을 복원하지 못함 |
| 모델 출력 | reasoning·text·tool_call 이벤트 시각이 있음. 토큰별 생성 시각이나 서버 내부 처리 시각은 아님 |
| 도구 호출·완료 | `emitted_at`·`result_at`이 있으나 일부 완료 기록 결측. 세션 전체의 현재 실행 여부를 완전하게 알려주지는 않음 |
| 사용량 보고 | Codex는 전 행에 `usage_report` 존재. Claude 140,338행에는 명시적 사용량 보고 시각 없음 |
| 실제 수집 지연 | 이벤트 이후 로그가 언제 수집 시스템에 도달했는지는 확인 불가 |

Codex의 마지막 출력 기록에서 사용량 보고 기록까지의 차이는 중앙값 **0.054초**, 99분위 **68.2초**, 최대 **약 13.2일**이었다. 600초 초과는 587건, 하루 초과는 13건이다. 이는 기록 사이의 시각 차이이며 서버 처리시간이나 공급자의 순수 보고 지연으로 단정하지 않는다.

입력 토큰도 응답 이후 보고된 수치일 수 있다. 예비 실험에서는 입력 길이까지 포함해 **사용량 보고가 관측된 뒤에만** 과거 특징으로 사용했다. Claude의 최종 사용량 확정 시점을 임의로 출력 이벤트 시각으로 대체하지 않았다.

### 3.3 토큰 정의와 품질의 한계

릴리스 당시 공개 추출 코드를 대조했다. Claude는 같은 메시지의 여러 사용량 기록에서 더 완전해 보이는 값을 선택하고, Codex는 누적 사용량 자체가 아니라 `last_token_usage`를 호출별 값으로 저장한다. 정규화된 수치에 다시 차분을 적용하지 않았다. 비공개 원시 로그나 공급자 회계의 정확성까지 검증한 것은 아니다.

- Claude 전체 입력 = 미캐시 입력 + 캐시 쓰기 + 캐시 읽기.
- Codex 전체 입력 = 캐시 읽기 + 나머지 입력. 별도 캐시 쓰기 카운터는 없음.
- 원본 입력 합에서 캐시 읽기 비중은 Claude **95.82%**, Codex **95.67%**.
- Codex 출력에는 reasoning이 포함되므로 다시 더하지 않음. Claude의 분리된 reasoning 필드는 결측.
- `newly_append_tokens`를 모두 의미상 새 내용으로 해석하지 않음.
- 문맥 길이는 압축·초기화 등으로 줄어들 수 있으므로 감소를 오류로 자동 삭제하지 않음.
- 전체 입력 토큰량을 GPU 계산량·비용과 동일시하지 않음.

### 3.4 희소성·수집 완전성·구성 변화

전체 Codex 보고 시간 범위의 내부 1분 구간 중 **87.43%**에는 보고가 없었다. 보고가 가장 많은 연속 24시간에는 12,170행이 있고 빈 분 비율은 **1.94%**였다. 활동이 밀집한 구간은 있지만 수집 heartbeat나 참여 기간 명세가 없어 연속 수집을 입증할 수는 없다.

예비 실험의 2026년 5월에는 분별 보고가 없는 비율이 **63.14%**, 다음 10분에 보고가 하나도 없는 목표 구간이 **47.63%**였다. 이 0은 **기록된 보고의 부재**이며 실제 무요청·무실행 또는 무토큰 생성의 확정값이 아니다.

관측 집단·모델 구성도 기간별로 달라진다. 예비 실험의 보고 사용자는 학습 11명, 검증 9명, 평가 6명이다. 가장 많은 모델의 보고 비중은 학습 90.28%, 평가 98.89%였다. 실제 참여자 증감인지 과거 로그 기증·수집 범위 차이인지는 구분할 수 없다. 이 관측 집단의 합계를 전체 코딩 에이전트 서비스 수요의 대표 표본으로 일반화하지 않는다. 사용자 간 시계 동기화도 미검증이다.

전체 품질은 [audit.json](../../eda/agent_transition/tracelab/results/audit.json), 시간·반복 기록은 [temporal.json](../../eda/agent_transition/tracelab/results/temporal.json), 날짜별 집계는 [daily.csv](../../eda/agent_transition/tracelab/results/daily.csv), 월별 구성은 [monthly_composition.csv](../../eda/agent_transition/tracelab/results/monthly_composition.csv)에 있다. 날짜별 집계는 첫 모델 출력 이벤트 기준이며 서버 도착일이 아니다.

## 4. Exgentic: 보조 후보의 표본 검증

- 배포 revision: `6b1add7c19f1fb50bb0edf5b240d6149a5c621fb`
- 전체 크기: 파일 목록 기준 39개 Parquet, 983,592,848바이트
- 확보 범위: 첫 파일 1개, 24,144,062바이트. 제공 파일 해시와 일치
- 공식 카드상 라이선스: CDLA Permissive 2.0

**직접 확인한 범위는 전체 데이터가 아니라 AppWorld 46세션·925 LLM span이다. 이 표본에는 SWE-bench가 없다.** 시작·종료 시각, 입력·출력 토큰 결측과 음수는 없었다. 입력·출력 0은 각각 52개 span이었다. 카드 예시와 달리 표본에는 `parent_span_id` 필드가 없었다. `collected_at`은 수집·내보내기 시각이며 요청 시각으로 사용하지 않았다.

전체 1,781개 실행·6개 벤치마크는 공식 카드의 주장까지만 확인했다. 전체 원본이나 코딩 전용 부분의 품질을 검증한 것은 아니다. 벤치마크 일정이 만든 시간축이므로 TraceLab과 합쳐 실제 서비스 수요라고 부르지 않는다. **벤치마크 내부의 호출·시간·토큰 구조를 비교하는 보조 자료**로 한정한다. [표본 결과](../../eda/agent_transition/exgentic/results/audit.json)

## 5. 제안하는 예측 문제와 A/B/C

주 데이터는 **사용량 보고 시각이 명시된 TraceLab Codex 부분**을 추천한다. 단, 아래처럼 보고 기준 목표로 변경하는 데 팀의 동의가 필요하다.

```text
예측 시점: UTC 매 1분 경계 t
목표 구간: [t, t + 600초)
호출 i의 보고 시각: r_i

Y_input(t)  = sum(전체 입력 토큰_i for t <= r_i < t + 600)
Y_output(t) = sum(전체 출력 토큰_i for t <= r_i < t + 600)

과거 특징: r_i < t인 보고만 사용
학습 정답 확정: 해당 보고 구간이 끝난 뒤
```

이 정답에는 이전에 실행됐지만 미래 구간에 사용량이 보고된 호출도 포함된다. 기존 PRD의 도착 기준 정답이나 구간 내 실제 생성량과는 다르다. 보고 시각을 로컬 관측 가능 시각으로 사용하는 가정은 두었지만, 이후 수집·전송 지연은 검증하지 못했다.

### 5.1 지평의 근거와 한계

10분은 기존 설계와의 비교를 위한 기본안으로 유지했다. 인간 대화 EDA를 에이전트 지평의 근거로 재사용하지 않았다. 5월의 미래 구간에 보고가 없는 비율은 다음과 같다.

| 지평 | 보고가 없는 목표 비율 | 집계 시점 수 |
|---|---:|---:|
| 1분 | 63.14% | 44,640 |
| 5분 | 52.06% | 44,636 |
| 10분 | 47.63% | 44,631 |

이는 희소성 기술 통계이며 성능 비교가 아니다. 지평별 끝부분 적격 시점 수가 다르고, 10분이 최적이라고 판단하지 않았다. 지평 선택 실험을 한다면 동일한 적격 시점·시간 분할에서 검증 구간으로 선택하고 평가 구간을 고정해야 한다.

### 5.2 최소 파이프라인과 특징

`공개 원본 보존 → 호출 메타데이터·품질 검사 → 보고 기준 1분 집계 → 과거 특징·미래 정답 → 시간순 분할·정답 확정 검사 → 기준 예측 및 A/B/C → 목표별·기간별 평가`

| 모델 | 실제 예비 실험의 특징 | 개수 |
|---|---|---:|
| A | 보고 수·입력·출력의 지연값과 이동 통계, 입력 길이 분포, 모델 구성비, 캐시·0입력 통계, 시간대 | 46 |
| B | A + 최근 5·15·30분 고유 보고 세션 수 | 49 |
| C | B + 최근 세션의 최근성·관측 연령·과거 보고 횟수·마지막 보고 입력 길이·입력 길이 변화의 중앙값·90분위 | 59 |

모델 구성과 단순 입력 길이 통계는 A/B/C에 공통 제공했다. ID는 연결키로만 사용했다. 이후 호출이 없다는 사실로 과거 종료를 판정하지 않았고, 미래 도구 결과·최종 단계 수·성공 여부·실제 남은 시간도 넣지 않았다.

**활동은 “최근 보고가 관측된 세션”이라는 조작적 정의다. 현재 실제 실행 중이라는 뜻이 아니다. 이번 C는 사용 이력 상태이며 도구 대기 등 실행 상태 특징의 실험은 미수행이다.**

## 6. 예비 실험의 실제 설정과 결과

### 6.1 실행 설정

| 항목 | 실제 설정 |
|---|---|
| 데이터·기간 | TraceLab Codex, 보고 기준 UTC 2026-05-01 이상~2026-06-01 미만 |
| 분할 | 시간 길이 기준 앞 60% / 다음 20% / 마지막 20% |
| 학습 경계 / 평가 시작 | 2026-05-19 14:24 UTC / 2026-05-25 19:12 UTC |
| 학습·검증·평가 시점 | 26,775 / 8,919 / 8,919 |
| 경계 제외 | 목표 구간이 다음 분할과 겹치는 18시점 |
| 모델·튜닝 | 입력·출력별 HistGradientBoosting A/B/C, 총 6개. 튜닝 없음, 공통 설정 |
| 목적·지표 | absolute error 학습, 주 지표 MAE, 보조 RMSE |
| 모델 선택 | 검증 MAE로 입력·출력 모두 B 선택. 평가 오차로 재선택하지 않음 |

기존 환경에 XGBoost가 없어 추가 설치 없이 기존 scikit-learn의 HistGradientBoosting으로 예비 비교했다. **PRD의 XGBoost 실험이 완료된 것은 아니다.** 환경은 Python 3.13.5, NumPy 2.1.3, pandas 2.2.3, scikit-learn 1.6.1이었다.

### 6.2 평가 구간 결과

다음 10분 누적 목표에 대한 토큰 단위 오차다. 아래 값은 정수로 반올림했다.

| 방법 | 입력 MAE | 출력 MAE | 입력 RMSE | 출력 RMSE |
|---|---:|---:|---:|---:|
| 직전 10분 보고 토큰 합계 유지 | 1,310,477 | 4,380 | 2,713,160 | 8,942 |
| 최근 60분 평균 × 10 | 1,455,655 | 4,876 | 2,711,851 | 8,978 |
| A | 1,108,859 | 3,697 | 2,305,177 | 7,955 |
| B | 1,104,945 | 3,708 | 2,302,398 | 8,006 |
| C | 1,119,364 | 3,707 | 2,351,655 | 7,913 |

- B는 A 대비 입력 MAE가 약 **0.35% 감소**했지만 출력 MAE는 약 **0.31% 증가**했다.
- C는 A 대비 입력·출력 MAE 모두 개선하지 못했다. 출력 RMSE는 조금 낮지만 지표 전반의 일관된 개선은 아니다.
- 예측 시점을 10분 간격으로 줄여 목표가 겹치지 않는 892시점만 보면 입력 MAE는 A 1,069,279, B 1,071,967로, B가 약 **0.25% 나빠졌다**.

**최근 세션 수나 상태의 일관된 추가 예측가치는 확인되지 않았다.** 그렇다고 코딩 에이전트 상태가 언제나 무용하다는 일반적 결론도 내릴 수 없다.

### 6.3 결과의 한계

- 전체 기간 EDA를 먼저 확인했으므로 완전히 보지 않은 확증 평가 구간이라고 주장하지 않는다.
- 평가 기간은 약 6일이며 10분 목표가 매 1분 겹친다. 분별 오차를 독립 표본으로 가정한 유의성 주장은 하지 않았다.
- 기록 부재와 미수집을 구별하지 못하고, 사용자·모델 구성이 기간별로 달라진다.
- 4월의 반복 기록이 두 세션의 과거 C 요약에 영향을 줄 수 있다. 두 세션에 속한 5월 보고는 1,099행이다. 5월 정답에는 해당 반복 기록이 없다.
- C는 사용 이력 상태까지 검토했으며 실행 상태의 효과는 미검증이다.
- 실제 서비스 전체·다른 조직·모델·기간 또는 GPU 부하·비용·전력 절감으로 일반화하지 않는다.

설정은 [pilot_config.json](../../eda/agent_transition/tracelab/results/pilot_config.json), 전체 지표는 [pilot_metrics.csv](../../eda/agent_transition/tracelab/results/pilot_metrics.csv), 일별 오차는 [pilot_daily_mae.csv](../../eda/agent_transition/tracelab/results/pilot_daily_mae.csv), 분할별 구성은 [pilot_periods.csv](../../eda/agent_transition/tracelab/results/pilot_periods.csv)에 있다.

## 8. 교수님께 제안할 설명과 남은 결정

> 공개 코딩 에이전트 로그에서 향후 10분간 사용량이 보고될 입력·출력 토큰량을 예측하고, 최근 세션별 관측 상태가 집계 이력보다 추가 예측가치를 제공하는지 평가하겠습니다. 서버 도착량이나 GPU 부하 예측으로 해석하지 않으며, 상태 추가가 유리하다는 가정 없이 비교하겠습니다. 예비 실험에서는 상태 추가의 일관된 개선이 확인되지 않았습니다.
